# differometor_native: API compatibility

Status of the native Python API against upstream Differometor
(`artificial-scientist-lab/Differometor` at `b0dc7c7`, plus the `signal_solver`
and `pack_noise` options from the updated `differometor.zip`). The upstream
source is the reference; where its docstrings and code disagree, the code wins.

The package is `differometor_native`, so the JAX package `differometor` stays
importable as the correctness reference. Its public surface is the same as
upstream's, so it can later be installed under the upstream name.

## Architecture

```
Python                          native (C++20, no Python, no JAX)
------                          ---------------------------------
Setup (mutable, Python)
  | setup_spec()  ------------>  SetupSpec       immutable snapshot
  | build_plan()  ------------>  SimulationPlan  immutable: ports, instructions,
  |                                              sparsity, sweeps, detectors
  | Simulator(plan) ---------->  Simulator       reusable workspaces
  |   forward / forward_with_state / backward
  v                              SimulationState tape + LU factors for backward
run / run_build_step / run_simulation_step / simulate  (upstream adapters)
```

- **Core library (`dfm_core`):** no Python and no JAX. It contains `SetupSpec`,
  `build_plan`, `Simulator`, `SimulationState`, the detectors, `ComplexSparseLU`
  and `solve_recorded` (a sparse solve that goes on the CoDiPack tape as one
  operation).
- **Bindings (`bindings/module.cpp`):** the only Python-aware C++. It is
  `differometor_native._native` with the submodules `core`, `detectors`,
  `linalg`, `diagnostics` and `constants`.
- **Python layer:** `setups.py`, `plot.py` and `utils.py` are copied from
  upstream. `components.py` is generated by `tools/generate_components.py`.
  `simulate.py` holds the adapters, `native.py` the new plan/simulator API, and
  `_convert.py` the one place where Python data crosses into native types.
- **Indirection:** none in the hot path. There is no virtual dispatch. Plan
  internals are read directly by the simulator, and link functions are an
  enum evaluated through a `switch`.
- **Runtime sizes:** every size is a runtime value. One binary serves any
  supported geometry, sweep length or parameter count, with no recompilation.

## Ownership and lifetime

| Object | Mutability | Owned by Python as | Keeps alive |
|---|---|---|---|
| `Setup` | mutable | plain Python object | nothing |
| `SetupSpec` | immutable | `shared_ptr` | nothing |
| `SimulationPlan` | immutable | `shared_ptr` | its `SetupSpec` |
| `Simulator` | owns workspaces | unique | its plan |
| `SimulationState` | opaque | unique | its plan |

- **Garbage-collection order never matters:** each object keeps alive what it
  points at.
- **Snapshots:** a plan built from a `Setup` does not change when the `Setup`
  is mutated later. Build a new plan to pick up changes.
- **Threads:** a `Simulator` is not thread-safe; use one per thread.
- **States:** CoDiPack's tape is per thread, so only the newest
  `SimulationState` recorded on a thread can be passed to `backward`. An older
  state, or one from another thread or plan, raises `RuntimeError` instead of
  returning wrong gradients.
- **GIL:** released while `forward`, `forward_with_state` and `backward` run
  native code.

## Arrays and dtypes

- **Dtypes:** inputs are converted to `float64`, `complex128` or `int32` (CSC
  indices). Outputs are `float64`, `complex128` or `int64` (port metadata).
- **Copies:** C-contiguous inputs of the right dtype are viewed in place, not
  copied. Outputs are moved into NumPy arrays without copying the elements.
- **Matrix layout:** row-major, so matrices map onto NumPy without transposes.
- **Shapes** (upstream convention, as returned by `run`):
  - carrier: `(carrier_ports, carrier_values)`
  - signal: `(signal_variables, signal_values)`
  - noise: `np.squeeze` of `(noise_detectors, signal_values)`

## Compatibility by module

### Top level

Exports match upstream: `Setup`, `run`, `run_build_step`,
`run_simulation_step`, `simulate`, `visualize_setup`, `power_detector`,
`signal_detector`. When Plotly is not installed, `visualize_setup` is a thin
shim that raises `ImportError` when called. Upstream instead fails at import
time.

### `setups`

The upstream file, copied unchanged except that link callables in the
predefined setups are `np.sqrt` instead of `jnp.sqrt`, which avoids importing
JAX. These callables show up in `Setup.to_data()`. Everything else is
identical: `Setup`, `Nodes`, `Edges`, `voyager`, `aligo`, `uifo`,
`constrain_inter_grid_cell_spaces`, the validation errors, and ordering.

### `simulate`

| Function | Signature | Behaviour |
|---|---|---|
| `run` | identical | Same 8 values as upstream's code: carrier, signal, noise, detector / mirror / beamsplitter / isolator indices and `port_to_index` (its docstring lists only the first seven). |
| `run_build_step` | identical, including keyword-only `signal_solver='packed'` and `pack_noise=None` | Returns `simulation_arrays` plus the five metadata items, or `(elapsed, (arrays, metadata))` when `timeit=True`, as upstream's code does (its docstring differs). Built by the native planner (`docs/planner.md`). |
| `run_simulation_step` | identical | `jit_simulation` is accepted but has no effect: the engine is compiled ahead of time, so there is no JIT and no warm-up run. |
| `simulate` | identical: the 31 upstream positional arguments in upstream order, plus keyword-only `signal_sparsity`, `packed_signal`, `packed_noise` | See *Internal simulation arrays* below. |
| `run_setups` | identical | Same. |

`solve`, `update`, `expand_parameters` and the updated zip's
`component_coefficients` and `group_component_instructions` are JAX
internals. They are not provided.

### `components`

- **Same as upstream:** the constants, `DEFAULT_PROPERTIES`,
  `PARAMETER_BOUNDS`, `laser_np`, `directional_beamsplitter_matrix` and
  `nothing_matrix`.
- **Detectors run natively:** `amplitude_detector`, `power_detector` and
  `signal_detector`. `signal_detector` handles 1-D inputs and 2-D inputs with
  column broadcasting natively. Any other shape combination uses the upstream
  NumPy expression, so NumPy's broadcasting rules still apply.
- **Registered kernels:** the 19 functions in `FUNCTIONS` (`laser`, `surface`,
  `space`, ...) run natively with their upstream signatures. They take real
  parameters (complex input only when its imaginary part is zero) and return
  `complex128` NumPy arrays of length 4. Values match JAX to 1e-13; see
  `docs/kernels.md`.
- **Helpers:** `incidence_angle_*`, `phase_shift`, `reflectivity_*`,
  `transmissivity`, `optomechanical_phase_*`, `tuning_correction`,
  `standardize_output`, `mirror_matrix` and `beamsplitter_matrix` are upstream
  formulas with `jax.numpy` replaced by `numpy`.
- **`FUNCTIONS`:** keeps upstream order and length, so integer indices stay
  meaningful.

### `utils`

The upstream file, copied with `jax.numpy` replaced by `numpy`; every call
used there has identical semantics. The detectors it uses are the native
ones. `bounding_function` and `sensitivity_function` stay arbitrary Python
callables: these helpers run outside the simulation, so nothing needs to be
native.

## Differences that cannot be reproduced exactly

1. **JAX transformations.** `jax.jit`, `jax.grad`, `jax.vjp` and `jax.vmap` do
   not apply to native functions. Use
   `differometor_native.simulate.simulate_vjp(simulation_arrays, p)` (same
   shape as `jax.vjp`, and it accepts JAX-convention cotangents), or the
   explicit native API: `Simulator.forward`, `forward_with_state` and
   `backward(state, carrier=, signal=, noise=)`, which accepts arbitrary
   output cotangents. A JAX bridge (`jax.custom_vjp` + `pure_callback`) is
   possible later as a separate feature.
2. **Complex cotangent convention.** The native convention is
   `zbar = dL/dRe(z) + 1j*dL/dIm(z)`. JAX's is the complex conjugate. A JAX
   bridge must conjugate at the boundary.
3. **Parameter-link callables.** Upstream accepts any Python callable in a
   `(source, callable)` property link and calls it under JAX. Natively, links
   must be one of `identity, sqrt, square, exp, log, sin, cos, negative, abs`.
   Callables are recognised by identity from `numpy`, `math` and, if already
   imported, `jax.numpy`. Anything else (lambdas, user functions) raises
   `ValueError` when the setup is converted. Extending this needs either more
   enum entries or a separate callback mechanism that supplies both the value
   and its derivative.
4. **Internal simulation arrays.** `run_build_step` returns a
   `SimulationArrays` dict: the upstream array contract, plus a `.plan`
   attribute holding the native plan.
   - `simulate(**arrays)` finds that plan through the identity of the
     `parameters` array, and reads only `optimized_parameters` on each call.
     So replacing `arrays["optimized_parameters"]` works as upstream (the
     benchmark relies on this).
   - Editing structural arrays in place does not change the plan.
   - Calling `simulate` with arrays that `run_build_step` did not produce in
     this process raises `NotImplementedError`.
   - The arrays are exported by the native planner and match upstream's
     (`docs/planner.md`). The exceptions: `linking_function_indices` are
     native link ids, and the noise instruction order is deterministic rather
     than set order.
   - With `optimization_pairs`, `simulation_arrays["optimized_parameters"]`
     is `None`, as in upstream; callers set it before calling `simulate`.
5. **Batched `optimized_parameters`.** Upstream's 2-D form only exists under
   `vmap`. `simulate` accepts 1-D only and raises `ValueError` for other
   shapes. A native batch API can be added later.
6. **`changing_values`** may also be 1-D when there is exactly one changing
   pair. It is reshaped to `(1, N)`.
7. **Exceptions.**
   - Input validation raises `ValueError`, matching upstream where upstream
     validates.
   - Where upstream failed late with `KeyError` or `IndexError` inside the
     build, the native planner raises `ValueError` early, with a message.
   - Engine work not yet implemented raises `NotImplementedError`.
8. **Component kernels** take real parameters and return NumPy arrays, not
   `jax.Array`.
9. **`Setup` is not mutated by building.** Upstream `build` writes defaults
   and `"<edge>_source"` targets into the setup's dicts. The native planner
   works on a snapshot.

## Milestone status

**Implemented and tested.** Milestone 1 (API) on gcc 15 (WSL) and MSVC 2022 (Windows);
milestones 2–4 on gcc 15: 80 GoogleTest tests and 273 pytest tests (JAX and upstream references).
- Package import and the upstream export surface.
- Signatures and defaults of `run`, `run_build_step`, `run_simulation_step`,
  `simulate`, `run_setups`, `Setup.add`, `Setup.space`, the detectors and
  `utils`.
- `Setup` round trip, views and validation errors.
- Conversion of `voyager` and `aligo` to `SetupSpec`.
- Planner request validation.
- The 8-value order, shapes, dtypes and squeeze of `run`, using a clearly
  marked fake engine in the tests.
- Detectors against the upstream formulas.
- Sparse LU and the recorded solve.
- Milestone 2: native component kernels, sparse storage, recorded sparse
  solves and products with implicit adjoints, validated against JAX (see
  `docs/kernels.md`).
- Milestone 3: runtime planner and sparse carrier, signal and noise assembly
  (passive and recorded), validated against upstream on cavity, aLIGO,
  Voyager and UIFO (see `docs/planner.md`).

- Milestone 4: the full native simulation pipeline (carrier, signal, quantum
  noise), reverse-mode gradients for arbitrary output cotangents, and
  `simulate_vjp`. Validated against the unmodified simulator on all 13
  harness configurations, including the 193 benchmark gradients (see
  `docs/simulator.md`).

Nothing in the public API is stubbed any more.

Remaining limitations are listed in `docs/simulator.md`.
